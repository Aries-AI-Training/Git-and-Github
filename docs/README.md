# Git and GitHub Training

This repository is the first training workspace for learning Git, GitHub, VS Code, and real developer collaboration.

The goal is not only to learn commands. The goal is to practice how developers work inside a company: creating branches, writing clear commits, opening pull requests, receiving feedback, and improving the work step by step.

## Learning Materials

Read the files in this order:

1. [Git Basics](Git_Basics_1771123243.pdf)
2. [Git HEAD and Branches](Git_HEAD_and_Branches_1771296724.pdf)
3. [Git and GitHub](Git_And_GitHub_1771296756.pdf)

If any PDF does not open correctly, tell the trainer and request a new copy.

## Training Style

This training is beginner-friendly, but it follows a real company workflow.

Mistakes are expected. What matters is that every mistake becomes a lesson, a note, or an improved commit.

## Weekly Workflow

Each trainee should:

1. Read the assigned material.
2. Write notes in Markdown.
3. Practice the Git commands.
4. Push work to GitHub.
5. Open a pull request.
6. Receive review comments.
7. Fix the comments and update the pull request.

## Repository Rules

- Do not push directly to `main`.
- Create a new branch for every task.
- Use clear branch names.
- Write meaningful commit messages.
- Open a pull request for your work.
- Ask questions with context: what you tried, what happened, and what you expected.
- Keep your notes clear enough for another trainee to learn from them.

## Suggested Branch Names

Use names like:

```text
notes/git-basics-your-name
task/first-commit-your-name
practice/branches-your-name
```

## Suggested Commit Messages

Use clear messages like:

```text
Add Git basics notes
Practice branch creation
Update notes after review
Fix Markdown formatting
```

Avoid unclear messages like:

```text
update
fix
done
changes
```

## Suggested Folder Structure

Future tasks may use this structure:

```text
notes/
tasks/
submissions/
resources/
```

## First Task

Create your first notes file and submit it through a pull request.

Steps:

1. Create a new branch.
2. Create a file named `notes/git-basics-your-name.md`.
3. Write a short summary of what you learned from the Git Basics PDF.
4. Add at least five Git commands with a short explanation for each one.
5. Commit your work.
6. Push your branch.
7. Open a pull request.

## Definition of Done

A task is done when:

- The work is pushed to GitHub.
- A pull request is opened.
- The pull request has a clear title and description.
- Review comments are answered or fixed.
- The trainer approves the pull request.
